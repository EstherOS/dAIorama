## [3] notes
===================================================================
- **Image rows are digest rows, live.** The generator accepts only the two platforms the lane
  builds, only 64 lowercase hex, refuses a tag as `invalid sha256`, and writes the pinned slug
  name with `size: 0`. Both verifiers accept the row; neither can be satisfied by a local file,
  which is the intended semantic (a registry digest is not a hash of any artifact).
- **The two implementations agree on the same freshly generated bytes**: same signer id, same
  artifact digest, same split between "untrusted key <id>" and "release signature verification
  failed", and the script refuses an empty trust list before it looks for `minisign`.
- **Divergence, recorded not scored:** the script is a signature/format/artifact-digest check
  (09 line 35 describes exactly that) and does not re-validate row schema. On a re-signed
  manifest whose file row carries `size: 0`, the binary refuses with `field "size" has invalid
  value` while the script accepts. Installs still refuse on the binary side; if the script is
  ever asked to be a full second verifier this is the gap to close.
- **The previous pass's byte-form note is resolved:** cc7cb9d makes the generator emit
  `"name":"…"` with no space, matching the pinned `grep -F` extractor in 09 (checked here on the
  image row too, which is the row an installer will read for digests).
- No product defect was found on this tree. The three probe defects fixed during the run were
  mine (the harness ran in a bench without `git`, a crafted signature had an all-zero key id, and
  a narrowed `PATH` broke `dirname` before the intended assertion); the corrected run is the one
  quoted above.
