1. **Gate instability fixed — `Text file busy` in the capture legs (test fixtures).**
   The capture tests pointed the runner at a `capture.sh` this process wrote. Under load
   (`cargo test` x3 concurrently on a cold cache) 2 of 3 runs failed with
   `capture failed: cannot start /tmp/.tmpXXXX/capture.sh: Text file busy (os error 26)` —
   a thread's fork duplicates the open write handle of another thread's freshly written
   fixture, and exec refuses while any handle on that inode is open for writing. Serial runs
   were green, so the flake only ever showed under parallel load. The fixtures now run their
   body as `/bin/sh -c <body> ... <out>` (`$1` is still the output path the runner appends),
   so no process execs a file it wrote. After the fix: one serial + three concurrent runs of
   the capture suite = 4/4 green (8 tests each), and the full workspace run is unaffected.
   This is a fixture-level fix, not a behaviour change to `run()`.

2. **D5 probe drift after #95.** `run-dashboard-install.sh` still expected a refused first
   install to leave an *empty* `modules/daiorama-dashboard/` behind (the nit measured at
   cdc269a). #95 changed the contract: a refused first install removes both levels it
   created, which the in-tree contract test pins (`!modules(..).exists()` in

   The probe now asserts `ABSENT`, and the D5 leg is 50/50 green on this tip.
